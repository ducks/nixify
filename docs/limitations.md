# Limitations

- Only Manjaro package and systemd service discovery is implemented. System and user service scopes may be inaccessible, especially without a running user manager or system bus; unavailable means unknown. Desktop discovery is limited to known package names, a small set of fixed session-file paths and recognized current-process XDG hints. Missing or inaccessible session files may be unknown; the configured desktop and display-manager configuration are not determined. Hardware discovery is partial: CPU model, visible EFI interface, PCI display/network devices and limited lsblk evidence only. USB, fstab, network settings, device identifiers and non-system mounts are not collected. EFI absence does not prove BIOS, and lsblk evidence is not sufficient to generate disk configuration. Networking is limited to interface category counts, nameserver categories, installed firewall packages and recognized network-manager service state. It does not retain addresses, interface names, hostname, DNS domains, VPN or Wi-Fi configuration, or determine effective firewall rules. Resolver symlinks outside known locations are treated as unknown. No private configuration or broader user-environment discovery is performed.
- The output includes an incomplete flake, modules, report and inventory, but is not a bootable or installable NixOS configuration. `validate` checks syntax and can optionally check package-attribute presence against a user-supplied Nixpkgs checkout. An explicitly opted-in module check evaluates the trusted project with placeholder hardware settings and checks system package names and NixOS assertions; it is not full system derivation evaluation. It does not prove package equivalence, service behavior, builds or boot behavior. Checkout revision metadata is not authenticated; matching `.git-revision` is not proof of identical content. The generated commit pin is not resolved and no lock is created automatically.
- Package and service mappings are small manually curated allowlists and are not checked against a target revision. Names can conceal differences in package features and behavior. Service enablement does not transfer unit overrides, dependencies, secrets or application data; runtime-only and user services need manual review.
- Foreign packages may be local, third-party, removed from sync repositories, or AUR; no specific provenance is inferred. Packages marked explicitly installed may have been selected by the original system image or installer.
- Baseline overlap is exact `pname` comparison against a minimal NixOS configuration evaluated from the specified checkout. It is not behavioral equivalence or a full source-to-target package mapping, and does not suppress generated packages. The target might use different modules or a different Nixpkgs revision.
- Queries are separate snapshots; database inconsistencies are detected where possible, but changes that preserve set membership can go unnoticed. The process times out after 30 seconds and limits captured output to 4 MiB per stream.
- Nix package builds and live baseline evaluation may require access to the Nix daemon or other local Nix resources. This environment cannot access the daemon socket; `nix build` and `nix flake check` remain unverified here.
