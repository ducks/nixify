# Architecture

`manjaro` detects `/etc/os-release` ID exactly and executes bounded, timed read-only pacman queries through argument arrays. `inventory` defines a versioned, validated serde schema. The scanner retains all installed packages, versions, explicit flags and foreign flags, and refuses inconsistent query snapshots. `mapping` uses a small curated allowlist; unknown and foreign names never become arbitrary Nix expressions. `output` generates a deterministic module and report from sorted records and refuses to overwrite existing files. The CLI orchestrates these modules; it does not require Nix for scan, report, or generation.

An optional `baseline` evaluates a minimal NixOS configuration from a user-supplied local Nixpkgs checkout with `nix-instantiate --eval --strict --json`. It reads `environment.systemPackages` `pname` values, records Nixpkgs version/path and platform, and reports exact name overlaps as tentative hints. Evaluation does not build or activate a system. Nixpkgs checkout paths and versions are evidence, not proof of a pinned revision or of equivalence with an eventual target configuration.

Pacman's `-Q` gives installed packages and versions, `-Qqe` gives explicit install reasons, and `-Qqm` returns packages absent from configured sync databases. These flags do not identify who installed a package or prove AUR provenance. See the [pacman manual](https://man.archlinux.org/man/pacman.8) and [os-release specification](https://freedesktop.org/software/systemd/man/latest/os-release.html). NixOS documents the [systemPackages option](https://nixos.org/manual/nixos/stable/options.html).

Future modules can add a scanner trait when a second distribution exists, explicit service and hardware evidence, revision-bound mapping checks, Nix syntax and module validation, and a generated flake. Future work could include Home Manager, an interactive wizard, VM equivalence testing, and nixos-anywhere integration; none is implemented.
