# Architecture

`manjaro` detects `/etc/os-release` ID exactly and executes bounded, timed read-only pacman queries through argument arrays. `inventory` defines a versioned, validated serde schema. The scanner retains all installed packages, versions, explicit flags and foreign flags, and refuses inconsistent query snapshots. `mapping` uses a small curated allowlist; unknown and foreign names never become arbitrary Nix expressions. `output` generates deterministic package, service and desktop modules, a flake skeleton and report from sorted records and refuses to overwrite existing files. The flake pins an explicit Nixpkgs commit but never resolves inputs or creates a lock; hardware and stateVersion are not invented. `draft` syntax-checks the fixed generated files using bounded `nix-instantiate --parse` calls. An optional check evaluates `builtins.hasAttr` for generated package names against a user-supplied local Nixpkgs checkout. It only accepts an unedited generated flake, packages module, and corresponding inventory. A checkout’s `.git-revision` is self-reported metadata, not proof of content identity. Syntax checking does not evaluate Nix code; the optional attribute check evaluates the supplied checkout and must only be used on trusted sources. Neither mode activates a system. `systemd` separately queries system and user unit files and running services, recording failures as unavailable. `service_mapping` translates a curated subset of persistently enabled system units into reviewable NixOS module enablements; runtime state alone never enables a module. `desktop` cross-references a small allowlist of installed package names, fixed session-file paths and recognized values of two XDG session variables. The variables describe the process environment, not a verified system default; unrecognized values and session-file contents are not retained. Generated desktop suggestions are comments only. The CLI orchestrates these modules; it does not require Nix for scan, report, or generation.

An optional `baseline` evaluates a minimal NixOS configuration from a user-supplied local Nixpkgs checkout with `nix-instantiate --eval --strict --json`. It reads `environment.systemPackages` `pname` values, records Nixpkgs version/path and platform, and reports exact name overlaps as tentative hints. Evaluation does not build or activate a system. Nixpkgs checkout paths and versions are evidence, not proof of a pinned revision or of equivalence with an eventual target configuration.

Pacman's `-Q` gives installed packages and versions, `-Qqe` gives explicit install reasons, and `-Qqm` returns packages absent from configured sync databases. These flags do not identify who installed a package or prove AUR provenance. See the [pacman manual](https://man.archlinux.org/man/pacman.8) and [os-release specification](https://freedesktop.org/software/systemd/man/latest/os-release.html). NixOS documents the [systemPackages option](https://nixos.org/manual/nixos/stable/options.html).

Future modules can add a scanner trait when a second distribution exists, custom unit, desktop and hardware evidence, revision-bound mapping checks, Nix syntax and module validation, and complete validated NixOS modules. Future work could include Home Manager, an interactive wizard, VM equivalence testing, and nixos-anywhere integration; none is implemented.
